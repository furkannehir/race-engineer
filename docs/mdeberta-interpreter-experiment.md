# mDeBERTa terminal experiment

An isolated, CPU-only alternative to the Laya playground. No live configuration,
ContextPlan, telemetry, STT, TTS, or Qwen behavior changes. No training. Inputs are
displayed in terminal scrollback but never saved by the demo. Each message is
independent; dialogue resolution is intentionally not part of this first test.

## Run from the repository root (PowerShell)

Use the existing isolated model runtime, not the main `.venv`. Setup downloads
approximately 1.1 GB of weights plus tokenizer files under ignored `data/`.
It does not install or upgrade packages. The runtime needs CPU PyTorch,
Transformers, and huggingface_hub (already present in the project's STT runtime).

```powershell
.\data\stt-prototype\runtime\Scripts\python.exe scripts\setup_mdeberta.py
.\data\stt-prototype\runtime\Scripts\python.exe scripts\try_mdeberta_interpreter.py
```

Setup needs internet once; inference loads local files only and sets Hugging Face
offline mode. The checkpoint stays resident during the interactive session.

```powershell
.\data\stt-prototype\runtime\Scripts\python.exe scripts\try_mdeberta_interpreter.py --language tr
.\data\stt-prototype\runtime\Scripts\python.exe scripts\try_mdeberta_interpreter.py --prompt "gap ahead" --raw
.\data\stt-prototype\runtime\Scripts\python.exe scripts\try_mdeberta_interpreter.py --language tr --prompt "Beni duyuyor musun?"
```

Type `/help` for commands: `/lang en`, `/lang tr`, `/raw on`, `/raw off`,
`/questions`, `/question-language matched`, `/question-language english`, `/quit`.
The language flag selects hypothesis wording, not a different model or translation.
Use typed console input or `--prompt` for Turkish; default PowerShell text pipes
can corrupt Turkish characters. Threads default to eight; `--threads 4` is available.

## What is being tested

Checkpoint: `MoritzLaurer/mDeBERTa-v3-base-xnli-multilingual-nli-2mil7`, pinned to
`b5113eb38ab63efdd7f280f8c144ea8b13f978ce`. Its model card lists an MIT license and
NLI training including English and Turkish. We download safetensors (not pickle
weights); inference uses float32 CPU and disables remote code.
See the [model card](https://huggingface.co/MoritzLaurer/mDeBERTa-v3-base-xnli-multilingual-nli-2mil7).

This is a pretrained **natural language inference** model, not a chatbot. Each
driver message is the premise; 17 declarative hypotheses describe possible
purposes, time scopes, and telemetry topics. One batched pass returns entailment,
neutral, and contradiction probabilities for every pair. Label order comes from
the checkpoint config. Input pairs are limited to 256 tokenizer tokens, truncating
the premise only; long messages can lose information.

The application constructs the displayed interpretation from those scores:

- Purpose and time scope: highest entailment score within each group. These are
  forced diagnostic choices, even when all hypotheses score poorly.
- Topics: independent full three-way entailment probability at least `0.5`.
  Neutral is not discarded. The threshold is an untuned baseline, not a validated
  acceptance threshold. More than one topic can be selected.
- `/raw on`: inspect all three NLI probabilities for every hypothesis.
- `duration_ms`: tokenization + the 17-pair CPU inference + conversion of model
  outputs. Cold model loading is shown separately; first inference may be slower.

The canonical labels match Laya's experiment, but probabilities are **not
calibrated and not numerically comparable** between models. The displayed JSON is
our scoring output, not JSON generated by mDeBERTa. No keyword overrides or
social/topic repair rules conceal failures. Hypothesis wording matters; this is
not an unrestricted semantic parser, referent resolver, or production router.

Try the same phrases that exposed Laya's problems: `Are you there?`, `That was
dirty`, `fuel`, `gap ahead`, `I know what I am doing`, `Am I last?`, `How's the race
looking?`, and `This guy is reckless, how much fuel do we have?`. Repeat in Turkish
using `/lang tr`; inspect raw scores and repeat timings before judging performance.
This exploratory demo has no accuracy pass/fail gate. If it looks promising,
evaluate bilingual held-out cases, ambiguity, compound requests, and latency under
gaming load before deciding whether to integrate it.

## Initial smoke checks (2026-10-10)

Using this machine, eight CPU threads, and a resident model, seven English
messages took approximately 230-281 ms each. Cold loading took about six seconds.
A Turkish single-shot `Yakıt durumumuz nasıl?` took 325 ms. These are smoke timings,
not a representative benchmark, gaming-load test, or end-to-end radio latency.

The shorter topic hypotheses recognized `fuel` and the Turkish fuel question.
However, `Are you there?` was incorrectly `out_of_scope`, `gap ahead` did not select
relative pace, and several plain questions were incorrectly `mixed`. The Turkish
fuel question selected the right topic but the wrong purpose. Basic separate NLI
sanity checks recognized clear entailment, contradiction, and neutral examples.
The model is runnable, but this hypothesis/scoring baseline is **not accepted** as
Pitward's interpreter. No rules were added to conceal these failures.
